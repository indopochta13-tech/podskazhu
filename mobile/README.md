# SoulVoice для Android — сборка и публикация в RuStore

Приложение для телефона собрано на Capacitor: интерфейс тот же, что в веб-версии, но экраны
лежат внутри приложения, а голос и напоминания работают через системные возможности телефона.

## Что уже сделано

| Готово | Требование RuStore |
|---|---|
| да | Формат APK и AAB, подпись действующим ключом |
| да | `targetSdkVersion` 36 при минимально допустимых 28 |
| да | Уникальное имя пакета `ru.soulvoice.app` |
| да | Нативные возможности сверх сайта: системное распознавание речи, напоминания без интернета, кнопки в шторке, работа офлайн |
| да | Вход внутри приложения, без переходов на сторонние сайты |
| да | Иконки всех плотностей, адаптивная иконка, системный экран запуска |
| да | Политика конфиденциальности по адресу https://soulvoicee.ru/privacy.html |
| нет | Аккаунт разработчика RuStore, скриншоты и заполненная карточка — это делаете вы |

64-битные библиотеки не требуются: нативного кода в приложении нет.

## Установить себе на телефон

Тот же подписанный APK лежит на сервере, поэтому телефону не нужен ни провод, ни облако:

**https://soulvoicee.ru/download/soulvoice.apk**

Страница загрузки: **https://soulvoicee.ru/download/**

1. Откройте эту ссылку в браузере телефона — файл скачается.
2. Нажмите на скачанный файл. Android спросит разрешение ставить приложения из этого
   источника — разрешите (это про браузер, а не про само приложение).
3. Откройте «SoulVoice», разрешите уведомления и доступ к микрофону.
4. Проверьте: скажите «завтра в 10 встреча» и нажмите в настройках «Отправить проверочное».

Файл на сервере — это копия `../app/public/download/soulvoice.apk`, она уезжает вместе с обычной
выкладкой сайта. После каждой пересборки копию нужно обновить, иначе по ссылке останется прежняя версия:

```bash
cp dist/soulvoice-1.9.29.apk ../app/public/download/soulvoice.apk
cp dist/soulvoice-1.9.29.apk ../app/public/download/soulvoice-1.9.29.apk
```

Через провод то же самое одной командой:

```bash
~/Library/Android/sdk/platform-tools/adb install -r dist/soulvoice-1.4.0.apk
```

## Виджет на рабочем столе

С версии 1.2.0 у приложения есть настоящий виджет Android. С 1.4.7:
две панели (сверху список ближайших — листается пальцем, снизу Чат / Запись / полка),
спокойные зелёные тона. Превью в каталоге без ListView — из‑за него раньше был пустой квадрат.

Ставится двумя способами: кнопкой «Настройки → Виджет на рабочем столе → Добавить на рабочий стол»
либо вручную через долгое нажатие на рабочем столе.

С версии 1.3.0 этот блок живёт только на рабочем столе. Раньше приложение открывалось его копией —
экраном с теми же тремя кнопками, — и это был лишний шаг. Теперь запуск сразу показывает полки,
а запись голосом переехала на круглую кнопку в правом нижнем углу списка.

Из чего состоит:

| Файл | Роль |
|---|---|
| `android/…/SoulVoiceWidget.java` | оболочка виджета и кнопки |
| `android/…/WidgetListService.java` | список ближайших записей для листания |
| `android/…/WidgetBridge.java` | плагин Capacitor: данные, нажатие, установка |
| `android/…/res/layout/widget_soulvoice.xml` | живой виджет: список + кнопки |
| `android/…/res/layout/widget_preview.xml` | превью в каталоге (без ListView) |
| `android/…/res/layout/widget_item.xml` | одна строка списка |
| `android/…/res/xml/soulvoice_widget_info.xml` | размеры и предпросмотр |
| `native/native.js` | `updateWidget`, `pinWidget`, `onWidgetAction` |
| `../app/public/app.js` | `widgetSnapshot()` — до 20 ближайших записей |

Своих данных виджет не добывает: приложение при каждом обновлении записей кладёт в
`SharedPreferences` готовый список, а виджет его только показывает. Пока приложение ни разу
не открывали, виджет показывает «Сегодня · Пока пусто».

## Как пересобрать

Нужны JDK 21 (берётся из Android Studio) и Android SDK.

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"

npm install
npm run apk:debug     # отладочный APK
npm run apk:release   # подписанный APK
npm run aab:release   # подписанный AAB для RuStore
```

### Версия перед RuStore / APK

Поднимайте **вместе** (один релиз — одно число везде):

| Файл | Поля |
|---|---|
| `android/app/build.gradle` | `versionName`, `versionCode` |
| `../app/public/app-version.json` | `versionName`, `versionCode`, `shellVersion`, `apkUrl` |
| `../app/public/app.js` | `APP_VERSION`, `SW_VERSION` |
| `../app/public/sw.js` | `SW_VERSION` |
| `../app/public/index.html` | `__VC_SHELL_V`, `app.js?v=` |

Сборка: `npm run aab:release` (RuStore) или `npm run apk:release` (прямая ссылка). RuStore берёт версию из манифеста AAB/APK. **В приложении нет кнопок обновления** — только RuStore или скачивание с сайта.

`npm run www` собирает папку `www`: копирует веб-версию из `../app/public`, убирает service worker
(в приложении он не нужен) и добавляет мост `native.js`. **Правки вносим в `../app/public`,
а не в `www` — она пересоздаётся при каждой сборке.**

## Звуки уведомлений

Файлы лежат в `android/app/src/main/res/raw/` (те же самые — в `../app/public/sounds`), их делает
`node ../app/tools/make-sounds.mjs`. Android намертво привязывает звук к каналу уведомлений:
у существующего канала сменить сигнал нельзя. Поэтому `native.js` создаёт по каналу на каждый звук
(`alarms_*`, `reminders_*`), а выбор в настройках просто переключает канал и пересобирает расписание.
Добавляете новый звук — заведите его и в `../app/public/sounds-catalog.js`, и в списках `native.js`.

Меняете набор целиком — старые каналы надо удалять руками через `RETIRED_CHANNELS` в `native.js`:
файла в приложении больше нет, а канал у человека остался и сработает молча. Старый выбор в настройках
переводит на близкий новый звук таблица `LEGACY` в каталоге, база чинится один раз при старте сервера.

## Поддержка в приложении

Обращения уходят оператору в телеграм-бот, ответ возвращается в переписку на экране
«Настройки → Поддержка» (см. раздел «Поддержка» в `../app/README.md`). Веб-пуша в приложении нет,
поэтому ответ ищет сам клиент: пока приложение открыто, раз в минуту опрашивает переписку,
а счётчик непрочитанного горит на иконке настроек в шапке.
Если приложение закрыто, ответ увидят при следующем запуске — счётчик и уведомление поднимутся сразу.

Найденный ответ показывает система, а не экран: `notifySupport` в `native/native.js` кладёт
уведомление в тот же канал, что и напоминания, — то есть с выбранным звуком. Иначе ответ приходил бы
молча: проиграть звук из кода WebView не даёт, ему нужно нажатие человека. При открытом приложении
система возвращает уведомление обратно, и поверх экрана появляется обычный баннер — уже без второго
сигнала, ровно как у напоминаний. Нажатие в шторке открывает переписку, прочитанный ответ из неё уходит.
Доставка при закрытом приложении — задача для RuStore Push SDK, она ждёт переезда сервера в Россию.

Адрес сервера по умолчанию `https://soulvoicee.ru`, меняется переменной:

```bash
VC_API_BASE=https://ваш-домен npm run aab:release
```

## Ключ подписи — самое важное

Ключ лежит в `keys/soulvoice-release.jks` (если локально ещё старое имя файла — обновите путь в `android/keystore.properties`), пароль в `android/keystore.properties`.
Оба файла не попадают в репозиторий.

**Сделайте копию обоих файлов в надёжном месте.** Если ключ потеряется, выпустить обновление
уже опубликованного приложения будет невозможно: RuStore принимает новые версии только с той же
подписью, и восстановление идёт через поддержку с потерей установок.

Отпечаток текущего ключа SHA-256:
`C1:C9:42:3E:6A:AE:5C:9F:7D:53:BB:58:1F:4E:89:7E:97:0D:21:AC:68:1D:E6:2D:9B:53:B2:19:1D:65:B4:48`

## Что понадобится для публикации

1. **Аккаунт разработчика** в RuStore Консоли — вход через Госуслуги. Подходит физическое лицо,
   самозанятый, ИП или компания. Сборка публикуется как бесплатная: подписка на тренажёр
   включается отдельно, когда подключён Pay SDK (раздел «Подписка RuStore Pay SDK»).
2. **Карточка приложения:**
   - название: SoulVoice;
   - короткое описание до 80 знаков: «Сказал или написал — задача с напоминанием уже стоит»;
   - полное описание: возьмите раздел «Что умеет» из `../app/README.md`;
   - иконка 512×512 — `store/icon-512.png`;
   - скриншоты: минимум 4, соотношение не мельче 9:16 (например 1080×1920). Снимите с телефона
     экраны: полки с записями, чат с ответом, карточку с колёсами, виджет на рабочем столе;
   - категория: «Продуктивность»; возрастная категория 12+;
   - ссылка на политику: https://soulvoicee.ru/privacy.html
3. **Загрузка:** `soulvoice-1.0.0.aab` плюс `rustore-upload-certificate.pem`. Либо просто
   `soulvoice-1.0.0.apk` — так проще, сертификат отдельно не нужен.
4. **Комментарий модератору.** Обязательно напишите, иначе легко получить отказ «обёртка над сайтом»:

   > Приложение работает без интернета: напоминания ставятся средствами Android и срабатывают
   > в авиарежиме, записи копятся в очереди и уходят при появлении связи. Голосовой ввод —
   > системное распознавание речи Android. В уведомлениях есть кнопки «+1 час» и «Сделано».
   > Регистрация не требуется: аккаунт создаётся автоматически при первом открытии,
   > персональные данные не запрашиваются. Тестовый вход не нужен — просто откройте приложение.

5. **Проверка занимает до трёх рабочих дней.** Отказ приходит с конкретной причиной, её можно
   исправить и отправить снова.

## Подписка RuStore Pay SDK

Тренажёр разговоров стоит денег на каждом разборе (модель + синтез речи), поэтому у него лимит:
на бесплатном тарифе три разбора в месяц, дальше — подписка. Всё остальное (записи,
напоминания, будильники, полки, наборы) бесплатно и без ограничений.

Пока оплата не подключена (нет `VC_RUSTORE_KEY`), сервер отвечает `testMode: true` и лимит не
включает: человек всё равно не может купить подписку, упираться в стену ему незачем. Боковая
шторка в приложении в этом режиме честно пишет «тестовый режим — всё открыто». Как только
ключ появится, лимит начнёт действовать сам, без правок в коде.

Серверная и веб-часть уже готовы: `GET /api/billing`, `POST /api/billing/purchase`,
`POST /api/billing/restore`, экран «Подписка» в настройках, лимит на `/api/sim/start`
и `/api/sim/prepare` (ответ 402 с кодом `NEED_PRO` открывает экран подписки).

Android-часть намеренно собрана без зависимости от SDK: `BillingBridge` проверяет наличие
класса `ru.rustore.sdk.pay.RuStorePayClient` и, пока его нет, отвечает «оплата недоступна».
Приложение при этом полностью работает и проходит модерацию как бесплатное.

Чтобы включить оплату, нужны данные из RuStore Консоли (их получает владелец аккаунта):

1. Идентификатор приложения (числа из адреса `console.rustore.ru/apps/<id>/versions`).
2. Подписки в разделе «Монетизация → Подписки» с идентификаторами `pro_month` и `pro_year`
   (именно эти строки знает сервер, см. `app/lib/billing.js`).
3. В `android/app/build.gradle`:

   ```gradle
   repositories { maven { url = uri("https://nexus-external.vkteam.ru/repository/maven-rustore-exposed/") } }
   dependencies {
       implementation platform("ru.rustore.sdk:bom:2026.07.01")
       implementation "ru.rustore.sdk:pay"
   }
   ```

4. В `AndroidManifest.xml`: `android:launchMode="singleTop"` у `MainActivity`, `intent-filter`
   с `android.intent.action.VIEW` и `<data android:scheme="ru.soulvoice.app.rustore" />`,
   плюс два мета-тега в `<application>`:

   ```xml
   <meta-data android:name="console_app_id_value" android:value="@string/rustore_app_id" />
   <meta-data android:name="sdk_pay_scheme_value" android:value="ru.soulvoice.app.rustore" />
   ```

5. Заменить тело `RuStorePayGateway.purchase/purchases` вызовами SDK
   (`RuStorePayClient.instance.getPurchaseInteractor()`), а в `MainActivity.onCreate/onNewIntent`
   добавить `RuStorePayClient.instance.getIntentInteractor().proceedIntent(intent)`.
   Контракт полей (`purchaseId`, `productId`, `status`) менять не нужно — сервер уже его понимает.

6. Проверять покупку сервером в боевом режиме: переменная `VC_RUSTORE_KEY` включает строгий режим,
   без неё сервер работает как в песочнице (`VC_RUSTORE_TEST=1` включает мягкий режим явно).

Пока пункты 1–5 не сделаны, экран подписки показывает: «Оплата доступна в приложении из RuStore».

## Выпуск следующей версии

1. Поднимите `versionCode` и `versionName` в `android/app/build.gradle` — RuStore не примет
   версию с прежним номером.
2. `npm run aab:release`.
3. Загрузите новый файл тем же ключом подписи.

## О чём стоит знать заранее

- **Где лежат данные.** Сервер сейчас за пределами России. Если приложением будут пользоваться
  граждане России, а в записях может оказаться персональная информация, по 152-ФЗ база должна
  находиться в России. Аккаунты у нас анонимны, но текст записей человек пишет любой —
  перед публикацией стоит перенести сервер на российский хостинг.
- **Уведомления о присланных записях.** Когда другой человек присылает вам напоминание,
  в веб-версии приходит push, а в приложении запись видна при следующем открытии. Мгновенное
  уведомление потребует подключения RuStore Push SDK — это отдельная задача.
- **Проверка на устройстве.** Подпись и содержимое пакета проверены сборкой, но виджет на живом
  телефоне ещё не запускался: эмулятора в системе нет, а поставить виджет на рабочий стол без
  launcher'а нельзя. Первый запуск на телефоне — обязательная проверка.
- **Подключение рядом по QR.** С версии 1.1.0 ссылка `https://soulvoicee.ru/?join=123456`
  открывает приложение и сразу показывает экран подтверждения. Собрано из трёх частей:
  intent-filter с `autoVerify` в `android/app/src/main/AndroidManifest.xml`, файл
  `../app/public/.well-known/assetlinks.json` с отпечатком ключа подписи и обработчик
  `appUrlOpen` в `native/native.js`, который отдаёт код в `NATIVE.onJoinCode`.
  Отпечаток в `assetlinks.json` обязан совпадать с ключом подписи — при смене ключа обновите файл,
  иначе Android перестанет открывать ссылки приложением и вернётся к вопросу «чем открыть».
  Фильтр закреплён за одним адресом — `android:path="/"`. Расширять его нельзя: подтверждённое
  приложение забирает себе все адреса, попавшие под фильтр, и «Правила» с «Что мы храним»
  открывали бы не браузер, а нас же — человек нажимал и оставался на прежнем экране. Так и было
  до 1.7.6, пока там стоял `pathPrefix="/"`.
  Ручной путь тоже остался: «Люди и группы» → «Подключить рядом» → поле «Меня позвали».
