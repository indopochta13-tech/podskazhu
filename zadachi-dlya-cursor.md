# Что сделать: сводка задач

Три пласта работы. Они не мешают друг другу и могут идти в любом порядке, но приоритет сверху вниз.

## 1. Поломка: виджет не ставится переключателем

В настройках есть «Виджет на рабочем столе». Включаешь — переключатель встаёт в положение «включено», а виджет на экране не появляется.

Причина неизвестна, нужен разбор. Вероятные места:

- `requestPinAppWidget` не вызывается или вызывается без проверки `isRequestPinAppWidgetSupported`
- вызов уходит, но результат не обрабатывается: человек отменил добавление, а переключатель всё равно остался включённым
- на некоторых прошивках (Xiaomi, Huawei) закрепление виджета запрещено системно — тогда нужно честное сообщение, а не молчаливый обман

**Как должно работать:** переключатель отражает реальность. Виджет не добавился — переключатель возвращается в выключенное состояние, и человек видит, почему.

Это единственная настоящая поломка в списке, остальное — доработки.

## 2. Оформление: по документу `etap-3-vneshniy-vid.md`

Документ обновлён, в нём появились новые разделы. Работать по порядку, отдельный коммит на раздел.

**Новое, чего не было раньше:**

| Раздел | Что делать |
|---|---|
| Темы и палитры | три режима темы плюс шесть палитр на выбор; все значения в документе |
| Шапка с обводками | подписка слева и настройки справа в кружках, списки посередине без рамки |
| Полоса полок | отдельный ярус под шапкой; только полки с содержимым; остальные за «ещё» |
| Будильник в списке дня | сейчас он спрятан во вкладке ежедневных дел, человек его не находит |

**Полоса полок заменяет экран «Ежедневные дела».** Сейчас туда свалены косметика, спорт, витамины, будильник и дни рождения — их объединяет только повторяемость. Это логика разработчика: человек ставит будильник и не может его увидеть.

**Про темы главное — не цвета, а поиск захардкоженных.** Значения готовы, их надо только вставить. Время уйдёт на другое.

Шесть палитр в двух темах — **двенадцать сочетаний**, и каждое нужно открыть на каждом экране. Где-то обязательно найдётся цвет, записанный числом мимо переменной, и он не переключится.

Самое опасное место — мелкий текст на приглушённом фоне: в светлых палитрах `--ink-muted` на `--surface-2` легко не дотянуть до читаемости. Если сомневаешься, темни текст, а не осветляй фон.

## 3. Персонаж: подготовка места

Владелец готовит набор монохромных лиц одного персонажа и отдельный набор символов. Когда они будут готовы, нынешние фигуры облака (галочка, часы, знак вопроса, улыбка, сердце, солнце, луна, восклицательный знак, точки, ладони) уходят целиком.

**Сейчас ничего не удалять и не переписывать.** Нужно только не мешать будущей замене.

### Как это будет устроено

Не одна фигура, а **два слоя**: лицо в нижней части круга и символ в верхней, где сейчас пусто.

Лицо отвечает на «как прошло»: записала спокойно, записала ночью, не расслышала. Символ отвечает на «о чём запись»: тележка для покупок, рукопожатие для встречи, капсула для лекарств.

Вызов будет выглядеть примерно так:

```js
cloud.show({ face: "saved", symbol: "cart" });
```

Пятнадцать лиц и двадцать четыре символа дают любое сочетание, и дорисовывать ничего не надо.

### Что от этого требуется сейчас

**Не завязываться на имена фигур в логике.** Код должен говорить «покажи реакцию на такое-то событие», а не «покажи галочку». Тогда замена пройдёт правкой одного места, а не поиском по всему проекту.

Если сейчас где-то стоит `cloud.showShape("check")` вперемешку с бизнес-логикой — стоит завести промежуточный слой: событие превращается в реакцию в одном месте, а всё остальное вызывает по имени события.

**Правило `isHeavy()` сохраняется и расширится.** Сейчас оно запрещает улыбку, сердце и солнце. С новым набором запретов станет больше: при тяжёлой теме допустимы только спокойное лицо и символы `hands`, `clock`, `dots`, `question`. Логика проверки та же — меняются только списки.

## Что нельзя трогать

```
verifyPurchaseWithStore()   clientIp()          revealShelvesFor()
daytimeAnswer()             TASK_VERB_RE        isHeavy()
try/catch в serveStatic     unhandledRejection  порог в autonomy.test.js
public/voice.js             public/icons.js     public/cloud.js
нативные будильники: ReminderScheduler, ReminderAlarmReceiver
проверка ctx.user в /api/start — без неё человек теряет аккаунт при каждом заходе
```

Полный список с причинами — в `SOSTOYANIE_PROEKTA.md`.

**Отдельно про три файла в `public/`.** Они написаны вручную и проверены: реплики выверены по русской грамматике, иконки взяты из Tabler с оптическим выравниванием, облако переписано трижды из-за развала фигур. Менять их не нужно — только подключать.

И не возвращать перехват путей `/voice.js`, `/icons.js`, `/cloud.js` в `server.js`. Из-за него приложение зависало на «загружается»: перехватчик читал файлы из `lib/`, а они лежат в `public/`. Они отдаются обычной статикой, как `sounds-catalog.js`.

## Проверка

```bash
npm run lint                 # 0 errors
node test/voice.test.js
# с поднятым сервером на 8791:
for f in test/*.test.js; do node "$f" >/dev/null 2>&1 || echo "ПАДАЕТ: $f"; done
```

В `api.test.js` ожидаются восемь провалов — старые, к нашей работе отношения не имеют.

**Обязательно открыть приложение в браузере после правок.** Ни один автотест не поймал зависание на «загружается»: линтер был чистый, тринадцать тестов зелёных, сервер отдавал 200 на все пути — а приложение не работало. Тесты идут в Node, браузер живёт по другим правилам.

Руками:

1. Все шесть палитр в обеих темах — ничего не пропало и не слилось
2. Переключение темы и палитры срабатывает сразу, без перезапуска
3. Кружки палитр в настройках показывают настоящий акцентный цвет
3. Виджет ставится переключателем и правда появляется на экране
4. Будильник виден в списке дня
5. Полоса полок показывает только заполненные
6. Шапка: крайние в кружках, средний без рамки
